# ١. طريقة استخدام هذه الحزمة

هذه الحزمة خطة كاملة جاهزة للتنفيذ لبناء **نظام مستقل للآليات** اسمه المؤقت **Equipment Flow** (يمكن تغييره). النظام **غير مرتبط بـ Team Flow نهائياً**: له قاعدة بيانات خاصة، وسيرفر خاص، ومستخدمون وتسجيل دخول خاص، ومواقع خاصة، وتطبيق Flutter خاص للموبايل والويب. استخدمنا نفس التقنيات التي يعرفها فريقكم (Node.js + MySQL + Flutter) حتى يكون التطوير والصيانة أسهل.

| الملف | المحتوى |
|---|---|
| 01 الخطة الرئيسية | النطاق، البنية التقنية، الأدوار، دورة العمل، القواعد، المراحل |
| 02 قاعدة البيانات | سكربت SQL كامل (25 جدول) جُرّب مرتين بدون أخطاء |
| 03 واجهات الباك إند API | هيكل المشروع، تسجيل الدخول والمستخدمين والمواقع، وكل endpoint للآليات |
| 04 محرك الحساب | قواعد الحساب بدقة + كود مرجعي + أمثلة محسوبة تُستخدم كاختبارات |
| 05 الورقة الشهرية والتقارير | تصميم الورقة الموقعة، الرفع، المطابقة، كل تقارير PDF و Excel |
| 06 تطبيق Flutter | التطبيق الجديد: تسجيل الدخول، التوجيه حسب الدور، كل الشاشات مع رسومات |
| 07 أوامر Claude Code والاختبار | خطوات العمل، أوامر جاهزة للنسخ لكل مرحلة، خطة الاختبار والإطلاق |
| 08 هذا الملف | الشرح الكامل بالعربي |
| source_files | ملفات SQL وكود الحساب جاهزة للنسخ كما هي |
| S1 / S2 | نموذج الورقة الشهرية ونموذج كشف مستحقات الشركة |

> **الخطوات باختصار:** أنشئ مستودعين فارغين (`equipment_flow_backend` و `equipment_flow_app`) بنفس المجلد، ضع هذه الحزمة داخل `equipment_flow_backend/docs/`، افتح Claude Code بالمجلد الأب، والصق "الأمر الرئيسي" ثم أمر المرحلة من الملف 07. مرحلة واحدة بكل جلسة، راجع وشغّل الاختبارات ثم انتقل للتالية.

# ٢. الهدف

١. تسجيل **دخول وخروج كل آلية** يومياً إلكترونياً من قبل مشرف الموقع.

٢. وجود **نسخة ورقية موقعة** بالتوازي: ورقة واحدة لكل آلية في كل موقع لكل شهر، وكل تسجيل جديد يضيف سطراً على نفس الورقة، ويوقّع على كل سطر **موظفنا** و**سائق الآلية**. تُرفع صورة الورقة على النظام وتُطابق **سطراً بسطر** مع التسجيل الإلكتروني.

٣. **لوحة مباشرة** تُظهر الآليات الموجودة بالمواقع في هذه اللحظة وحالتها (تعمل، استراحة، معطلة، متوقفة بانتظار عمل).

٤. استخراج **المستحقات (Payroll) عند الطلب** لأي فترة: لكل آلية، ولكل شركة، وملخص عام لكل الشركات، مع تسعير مرن لكل آلية.

٥. كل شيء يُصدَّر كملفات **PDF احترافية** بهوية الشركة، إضافة إلى Excel.

**خارج النطاق في النسخة الأولى:** أي ربط مع Team Flow، GPS، صيانة الآليات وقطع الغيار، القيود المحاسبية، قراءة الورقة آلياً (OCR)، بوابة خاصة بالشركات المؤجرة.

# ٤. المستخدمون والأدوار والصلاحيات

النظام له **مستخدمون خاصون به** وثلاثة أدوار:

- **الأدمن:** كل شيء — المستخدمون، المواقع وتعيين المشرفين، الإعدادات، البيانات الأساسية، الأسعار، الموافقات، المطابقة، المستحقات، التقارير، سجل التعديلات.
- **المحاسب:** يقرأ كل شيء، يسعّر المازوت، يضيف الإضافات والخصومات، يطابق الأوراق، يولّد المستحقات والكشوف. **لا يوافق على الدوام** (فصل الصلاحيات) ولا يدير المستخدمين.
- **المشرف:** يسجل دوام الآليات فقط في **المواقع والورديات المعيّن عليها بذلك التاريخ**، يطبع الورقة ويرفع صورتها، يسجل ليترات المازوت. **لا يرى أي سعر أو مبلغ.**

**تسجيل الدخول والأمان:**

- أول أدمن يُنشأ بسكربت.
- كل مستخدم جديد يأخذ كلمة سر مؤقتة ويُجبر على تغييرها أول دخول.
- كلمة السر 10 أحرف على الأقل.
- بعد 5 محاولات خاطئة يُقفل الحساب 15 دقيقة.
- كل محاولة دخول تُسجل.
- الدور والحالة يُقرآن من قاعدة البيانات مع كل طلب، أي أن تعطيل المستخدم يسري فوراً.
- لا يمكن تعطيل آخر أدمن.

**المواقع:** لكل موقع رمز (مثل S08) واسم، ووردية نهارية وليلية اختيارية، وأوقات بداية الوردية (للوحة "لم تصل"). يُعيَّن مشرف لكل موقع ووردية بين تاريخين، بدون تداخل.

# ٥. دورة العمل من البداية للنهاية

٠. **التجهيز (مرة واحدة):** إنشاء الأدمن، ثم المستخدمين (مشرفين، محاسب)، ثم المواقع وتعيين المشرفين.

١. **تسجيل الشركة** والعقد (الرقم، التواريخ، العملة، رفع العقد الموقع).

٢. **تسجيل الآليات** (النوع، الموديل، النمرة، رقم الشاصي، صورة) وسائقي الشركة.

٣. **التسعير:** بطاقة تسعير لكل آلية ضمن العقد (طريقة الحساب وكل الخيارات المرنة).

٤. **التوزيع:** تعيين الآلية على موقع ووردية من تاريخ معين (مع سائق افتراضي). الآلية لا يمكن أن تكون بموقعين بنفس اليوم.

٥. **الورقة الشهرية:** تُنشأ تلقائياً مع أول تسجيل للآلية في الشهر بالموقع، برمز مثل `ETS-2026-10-EQ0012-S08`، ويمكن طباعتها بأي وقت. كل تسجيل جديد يظهر كسطر جديد برقم ثابت لا يتغير.

٦. **التسجيل اليومي (تطبيق المشرف):** عند الوصول: تسجيل دخول (الوقت، السائق، قراءة العداد). خلال اليوم: استراحة / تعبئة مازوت / عطل / انتظار (بداية ونهاية وسبب). عند المغادرة: تسجيل خروج (الوقت، العداد، المازوت المستلم، العمل المنجز). وللأيام التي لم تعمل فيها: حالة يوم كامل (انتظار، عطل، غياب، عطلة رسمية).

٧. **التوقيع الورقي:** بنفس اليوم يوقع موظفنا والسائق على السطر.

٨. **الإرسال:** آخر اليوم يرسل المشرف اليوم للمراجعة (مسودة ← مُرسل). (إذا كان الخيار مفعلاً) لا يمكن إرسال يوم إذا بقيت مسودات من الأسبوع السابق.

٩. **المراجعة:** الأدمن يوافق أو يرفض (المرفوض يُصحح ويُعاد إرساله). التنبيهات (جلسة طويلة، عداد لا يطابق الساعات، خروج منسي، رخصة سائق منتهية...) يجب الاطلاع عليها قبل الموافقة.

١٠. **رفع صورة الورقة:** أسبوعياً (مستحسن) وإجبارياً آخر الشهر. كل رفع نسخة جديدة لا تُحذف ولا تُستبدل.

١١. **المطابقة:** الأدمن يفتح الصورة بجانب الأسطر الإلكترونية ويحدد لكل سطر: مطابق / غير مطابق / غير موجود. المطابق يتطلب وجود التوقيعين وفرق وقت لا يتجاوز 10 دقائق (قابل للتعديل).

١٢. **إغلاق الشهر:** بعد توقيع المهندس المقيم وممثل الشركة على المجموع ورفع الصورة النهائية. عندما تكون كل الأسطر مطابقة تصبح الورقة "مُطابقة بالكامل".

١٣. **المستحقات:** الأدمن يعاين ثم يولّد الحساب لأي فترة ونطاق. افتراضياً لا يُدفع إلا السطر **الموافق عليه والمطابق للورقة**. يوجد تقرير "الموانع" يشرح لماذا سطر ما غير قابل للدفع.

١٤. **الاعتماد ثم الدفع:** الاعتماد يقفل الأيام المحسوبة. أي خطأ بعدها يُعالج عبر "تصحيح رسمي" مع سبب، أو بإصدار نسخة جديدة من الدفعة (مع سبب) مع الاحتفاظ بالنسخ السابقة.

# ٦. أهم القواعد

**البيانات الأساسية**

- اسم ورمز الشركة فريدان؛ الشركة التي لها آليات لا تُحذف بل تُعطّل.
- **لكل عقد عملة واحدة** (دولار افتراضياً، والليرة مدعومة)، و**كل دفعة مستحقات بعملة واحدة**.
- السائق تابع لشركة واحدة؛ لا يُسمح باستخدام سائق شركة أخرى. الرخصة المنتهية تُسمح مع تنبيه.
- بطاقات تسعير الآلية الواحدة لا تتداخل بالتواريخ؛ والبطاقة المستخدمة بدفعة معتمدة لا تُعدّل — تُغلق وتُنشأ بطاقة جديدة من اليوم التالي.

**التسجيل اليومي**

- لا تسجيل إلا بيوم تكون فيه الآلية موزعة على الموقع والوردية، ولا تسجيل لتاريخ مستقبلي (بتوقيت بيروت).
- جلسة مفتوحة واحدة فقط للآلية بكل المواقع، ولا تداخل بالأوقات.
- الوردية الليلية تُسجل بتاريخ الدخول حتى لو كان الخروج باليوم التالي.
- فترات التوقف داخل الجلسة، غير متداخلة، وواحدة مفتوحة فقط بنفس الوقت؛ وتُغلق تلقائياً عند الخروج.
- العداد: النهاية ≥ البداية، والبداية ≥ نهاية آخر يوم؛ إذا اختلف فرق العداد عن ساعات العمل أكثر من 15٪ يظهر تنبيه.
- التنبيهات لا تغيّر أي قيمة؛ هي فقط تطلب المراجعة.
- الأيام المعتمدة في دفعة مستحقات **مقفلة** ولا تُعدّل إلا بالتصحيح الرسمي.

**الورقة**

- ورقة واحدة لكل آلية × موقع × شهر. رقم السطر ثابت للأبد (السطر المسجل بتاريخ قديم يأخذ الرقم التالي ولا يُدرج بالوسط)، لذلك إعادة الطباعة **تضيف أسطراً بالأسفل فقط**.
- صور الورقة لا تُحذف ولا تُستبدل؛ نفس الملف لا يُرفع مرتين (بصمة SHA-256).
- إذا صُحح سطر بعد مطابقته يعود "بانتظار المطابقة".

# ٧. التسعير المرن (كيف يُحسب المبلغ)

لكل آلية بطاقة تسعير فيها:

| الخيار | الشرح |
|---|---|
| طريقة الحساب | **بالساعة** أو **باليوم** أو **بالشهر** |
| ساعات اليوم القياسية | مثلاً 8 ساعات — تُستخدم لأيام الانتظار/العطل الكاملة ولحساب أجزاء اليوم والشهر |
| الحد الأدنى اليومي | مثلاً 6 ساعات مضمونة بأيام العمل والانتظار (اختياري) |
| الساعات الإضافية | تفعيل/إلغاء، بعد كم ساعة تبدأ، سعر الساعة الإضافية أو معامل ضرب |
| نسبة الانتظار | كم ٪ يُدفع من ساعة/يوم الانتظار (الافتراضي 50٪) |
| نسبة العطل | كم ٪ يُدفع من ساعة/يوم العطل (الافتراضي 0٪) |
| الاستراحة | تُخصم أو مدفوعة |
| حساب جزء اليوم (لليومي) | نسبي / يوم كامل إذا اشتغل / نصف يوم تحت حد معين |
| أيام العمل الشهرية (للشهري) | مثلاً 26 يوم لحساب قيمة اليوم والساعة المكافئة |
| السائق | مشمول بالسعر، أو يُضاف أجر يومي للسائق |
| سياسة المازوت | الشركة تؤمّنه (وأي مازوت نعطيه يُخصم) / نحن نؤمّنه ويُخصم / نحن نؤمّنه مجاناً |
| إضافات وخصومات يدوية | نقل الآلية، مكافأة، غرامة، أضرار... بمبلغ وسبب |

**الحد الأدنى:** يُكمَّل الفرق بين الحد الأدنى ومجموع (العمل + الانتظار + العطل)، أي أن ساعات العطل لا يعوّضها الحد الأدنى لأن العطل مسؤولية الشركة المؤجرة.

## أمثلة محسوبة (مُتحقق منها برمجياً)

**مثال أ — حفارة بالساعة:** 40$/ساعة، حد أدنى 6 ساعات، إضافي بعد 10 ساعات بـ 50$، انتظار 50٪، عطل 0٪.
الأيام: 9.5 ساعة · 12 ساعة (منها 2 إضافي) · 4.5 ساعة مع 3 ساعات عطل · 3 ساعات عمل + 2 انتظار (يُكمّل ساعة للحد الأدنى) · يوم انتظار كامل · يوم عطل كامل · غياب.
النتيجة: عمل 27 ساعة = 1,080$ · إضافي 2 ساعة = 100$ · انتظار 5 ساعات محسوبة = 200$ · تكملة الحد الأدنى 1 ساعة = 40$ · خصم مازوت 100 ليتر × 1.10 = −110$ · نقل الآلية +150$ ← **الصافي 1,460$**.

**مثال ب — تركس باليومي:** 300$/يوم، 8 ساعات، حساب نسبي، إضافي بعد 8 ساعات بـ 45$، السائق غير مشمول (20$/يوم).
الأيام: 8 ساعات = يوم · 10 ساعات = يوم + 2 ساعة إضافي · 5 ساعات (مع 3 عطل) = 0.625 يوم · انتظار كامل = نصف يوم.
النتيجة: 787.50 + 90 + 150 + سائق 60 ← **الصافي 1,087.50$**.

**مثال ج — رافعة بالشهري:** 6,500$/شهر، 26 يوم عمل، 8 ساعات.
الشهر كامل 6,500 − غياب يوم 250 − عطل 12 ساعة × 31.25 = 375 + إضافي 6 ساعات × 40 = 240 ← **الصافي 6,115$**. وإذا وصلت يوم 10 من الشهر (22 يوم من 31): 6,500 × 22 ÷ 31 = **4,612.90$**.

# ٨. الورقة الشهرية الموقعة

**ما المطبوع عليها:** شعار الشركة، العنوان بالعربي والإنكليزي، QR فيه رمز سري يمنع تزوير الورقة، الشهر، الموقع، الآلية، النوع، النمرة، الشركة، رقم العقد. ثم جدول: رقم السطر، التاريخ، الحالة، السائق، الدخول، الخروج، الاستراحة، العطل، الانتظار، ساعات العمل، العداد بداية/نهاية، المازوت، العمل المنجز، **توقيع الموظف**، **توقيع السائق**. ثم أسطر فارغة للتسجيل اليدوي إذا تعطل التطبيق، ثم المجاميع (بدون أي مبالغ) ومربعات توقيع المهندس المقيم وممثل الشركة والختم آخر الشهر.

**إجراءات الموقع:**

١. أول الشهر (أو عند وصول الآلية) يطبع المشرف ورقة كل آلية.

٢. كل يوم: تسجيل بالتطبيق + توقيع الموظف والسائق على السطر.

٣. أسبوعياً: إعادة طباعة (تظهر الأسطر الجديدة مطبوعة)، التوقيع، التصوير والرفع.

٤. آخر الشهر: توقيع المجموع ورفع الصورة النهائية.

**المطابقة بالمكتب (الأدمن أو المحاسب):** الصورة على اليسار والأسطر على اليمين؛ زر "مطابق للورقة" لكل سطر (الحالة الأكثر شيوعاً بنقرة واحدة)، أو إدخال القيم المكتوبة بالورقة إذا اختلفت؛ النظام يرفض "مطابق" إذا تجاوز الفرق 10 دقائق أو نقص أحد التوقيعين. لا يوجد زر "طابق الكل" عمداً — كل سطر يجب أن يُنظر إليه.

> **مهم جداً — حفظ الملفات:** صور الأوراق الموقعة دليل قانوني. كثير من الاستضافات (مثل Render بدون قرص) تمسح الملفات مع كل نشر، لذلك الخطة تعتمد طبقة تخزين على **تخزين سحابي S3** (مثل Cloudflare R2) أو قرص دائم. يجب إعداد أحدهما قبل الإطلاق.

# ٩. اللوحة المباشرة

لكل آلية موزعة اليوم: **تعمل** (أخضر) · **استراحة** (رمادي مزرق) · **معطلة** (أحمر) · **انتظار** (برتقالي) · **أنهت** · **لم تصل** · **غياب/عطلة** · **خروج منسي** (جلسة مفتوحة أكثر من 16 ساعة).
المؤشرات: عدد الموزعة، الموجودة الآن، التي تعمل، المعطلة، بالانتظار، التي لم تصل، ساعات العمل اليوم، **الكلفة التقديرية لليوم** (للأدمن فقط). تجميع حسب الموقع أو الشركة، وفلتر "المشاكل فقط"، وتحديث تلقائي كل 60 ثانية. المشرف يرى موقعه فقط وبدون مبالغ.

# ١٠. المستحقات والتقارير

- **معاينة** بدون حفظ ← **توليد** دفعة ← **اعتماد** (يقفل الأيام) ← **تم الدفع**. يمكن **إلغاء** الدفعة قبل الدفع، أو **استبدالها بنسخة جديدة** مع سبب بعد الاعتماد.
- النطاق: كل الشركات، أو شركة، أو آلية، أو موقع، لأي فترة.
- تقرير **الموانع**: سطر غير موافق عليه، غير مطابق للورقة، جلسة مفتوحة، تنبيه غير مُطّلع عليه، لا يوجد تسعير، مازوت بدون سعر، موجود بدفعة أخرى، عملات مختلفة.

| التقرير | الوصف |
|---|---|
| D1 الورقة الشهرية | للتوقيع، مع QR — بدون مبالغ |
| D2 كشف آلية | يومياً + بطاقة التسعير + بنود الحساب + الصافي |
| D3 كشف الشركة | كل آليات الشركة + المازوت + الإضافات/الخصومات + الصافي بالأرقام والكلمات + مربعات توقيع (يُعطى للشركة) |
| D4 ملخص المستحقات | كل الشركات في الدفعة — للمالية |
| D5 تقرير الموقع اليومي | كل آليات الموقع وحالتها — بدون مبالغ |
| D6 الاستفادة | نسبة تشغيل كل آلية لكشف الآليات المستأجرة غير المستغلة |

يمكن أيضاً إصدار **كشف مؤقت** لآلية أو شركة لأي فترة بدون دفعة، مع علامة مائية "مؤقت".

# ١١. الشاشات

**تسجيل الدخول:** شاشة دخول، تغيير كلمة السر إجباري أول مرة، ثم توجيه حسب الدور.

**الأدمن والمحاسب:** قائمة جانبية (أو شريط جانبي على الشاشات العريضة): اللوحة المباشرة · مراجعة الدوام · الأوراق والمطابقة · المستحقات · المازوت والإضافات · الآليات · الشركات · السائقون · المواقع · (للأدمن فقط: المستخدمون · الإعدادات · سجل التعديلات). نموذج بطاقة التسعير يحتوي لوحة **"جرّب هذا السعر"**: أسبوع تجريبي يُحسب فوراً لفهم أثر كل خيار.
