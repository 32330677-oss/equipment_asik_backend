# Paper Timesheet — & Documents

**Monthly signed sheet, scans, reconciliation, PDF & Excel reports**

How the paper copy is generated, signed, uploaded, versioned and matched with the electronic attendance, and the layout of every report.

_Equipment Flow · Doc 05 · v2.0 standalone · 2026-10-03_

---

# 1. Why a paper sheet, and how it stays trustworthy

The electronic attendance is what the system computes with; the paper sheet is the **signed evidence** that the vendor's operator and our employee agreed on each day. The design guarantees that the two cannot silently diverge:

1. The paper is **generated by the system** (not a free-form form) and carries a unique code and a QR with a secret token → a sheet cannot be invented or swapped.
2. Each electronic row has a **permanent row number** on its monthly sheet → the paper row and the database row are linked one-to-one.
3. Scans are **immutable and versioned** with a SHA-256 hash → nothing can be replaced after the fact.
4. A human **reconciles row by row**; payroll by default pays only rows that are Approved **and** Matched.

# 2. Site procedure (SOP for supervisors)

| When | Who | Action |
|---|---|---|
| 1st working day of the month (or machine arrival) | Supervisor | Print the month sheet of each machine (`Print sheet`) and keep it in the site folder. If the app is down the sheet still has blank rows. |
| Machine arrives | Supervisor | App: **Check-in** (time, operator, meter). |
| During the day | Supervisor | App: Break / Refuel / Breakdown / Standby start & end with reason. |
| Machine stops | Supervisor | App: **Check-out** (time, meter, fuel received, work done). |
| Same day | Supervisor + Operator | Write nothing new — the values are already printed when re-printed; if the sheet was printed before the row existed, write date / in / out / meter by hand in the next row. **Both sign the row.** |
| Every week (recommended) | Supervisor | Re-print the sheet (new rows now printed), sign the new rows, photograph / scan the full sheet, **Upload scan**. |
| Month end | Site engineer + vendor representative | Sign the monthly total box. Final scan uploaded. |
| After upload | Admin (approve) / Accountant (reconcile, close) | Reconcile rows; approve; close the sheet. |

<div class="note">Re-printing is safe: rows keep their numbers, so a re-printed sheet only <b>adds</b> lines at the bottom. Old signed pages stay valid; the scan of the latest page set is what is uploaded.</div>

- **Totals** of printed rows: days Working / Standby / Breakdown / Absent, work hours, breakdown hours, standby hours, fuel litres. (No money — the sheet goes to the site and to the vendor's operator.)
- **Month-end sign-off** boxes: Site engineer (name, signature, date) · Vendor representative (name, signature, date) · Stamp.
- Print stamp line: `Printed {YYYY-MM-DD HH:mm} by {user} · print #{print_count} · rows 1–{last_row_no} · Equipment Flow`.
- Legend line: "Standby = machine ready, idle by our decision · Breakdown = machine out of order".

# 4. Uploading scans

### 4.1 Client (Flutter)

- Sources: camera (multiple photos, one per page) or file picker (PDF / images). Use the `image_picker` and `file_selector` packages.
- Before upload, compress images to max 2000 px on the long side, JPEG quality 80 (`flutter_image_compress` optional; otherwise rely on `image_picker` `maxWidth`, `imageQuality`).
- Fields: `through_row_no` (pre-filled with `last_row_no`), note.
- Show progress; on success show "Version n uploaded".

### 4.2 Server

1. `multer.memoryStorage`, limits 15 MB/file, 10 files, magic-number check.
2. If several images → build one PDF (pdfkit: A4, each image fitted to page) so one version = one file; a single PDF is stored as is.
3. SHA-256 of the stored file → reject duplicates for the same sheet (`DUPLICATE_SCAN`).
4. `fileStorage.put` with key `equipment/timesheets/{sheet_code}/v{n}-{sha8}.pdf`.
5. Insert `eq_timesheet_scans` (`version_no = max + 1`), audit.
6. Rows with `sheet_row_no ≤ through_row_no` and paper status `Missing` go back to `Pending` (they may now be visible).

### 4.3 Viewing

`GET /timesheets/:id/scans/:scanId/file` streams `application/pdf` inline. Flutter shows it with the `printing` package (`PdfPreview` / `Printing.raster`) (part of the app dependencies). Images are never served from a public URL.

# 5. Reconciliation (Admin / Accountant)

Screen layout (doc 06): scan on the left (zoomable, page selector), rows on the right.

For each row the reviewer can:

- Click **Matches paper** → sends `result = Matched` with both signatures ticked and paper times = electronic times (one click for the common case).
- Or open the row editor: type the paper in/out/meter, tick the signatures found → server computes `diff_minutes` and accepts `Matched` only within tolerance and with both signatures.
- **Mismatch** → note required; the row stays out of payroll until corrected (Admin edit / correction) and re-checked, or rejected back to the supervisor.
- **Missing** → the row is not on the scan (e.g., scan older than the row).

Bulk: "Match all rows within tolerance" is **not** offered — each row must be looked at; a keyboard flow (↓ next row, M = matched, X = mismatch) keeps it fast.

Status updates: row `paper_status`, sheet counters, sheet `Reconciled` when Closed and all Matched.

# 6. Reports

Common visual identity (shared helpers in `services/pdfKit.js`): navy `#1A2A6C` header band and table heads, gold `#B8963E` accent line, zebra `#FAF9F6`, grid `#C9CCD3`, ink `#2F3034`, negative amounts `#C0392B`, logo left, company name, report title EN + AR, period, generation stamp, page x/y, Arabic text via Noto Naskh. Money right-aligned, currency code in column header.

## D2 — Machine Statement (A4 portrait)

1. Header: machine code, type, plate, vendor, site(s), period, batch no + version + status (or **PROVISIONAL** watermark).
2. Rate card box: mode, prices, minimum, OT, standby %, breakdown %, break policy, fuel policy, operator (from the snapshot).
3. Daily table: date · status · operator · in · out · work h · OT h · standby h · breakdown h · top-up h · meter Δ · sheet row · paper.
4. Lines table (from `eq_payroll_lines`): description · qty · unit · unit price · amount.
5. Totals: gross · deductions · **net payable**.
6. Signatures: Prepared by · Checked by · Approved by.

## D3 — Vendor Statement (A4 portrait) — the document sent to the vendor

1. Header: vendor name/code, contract no(s), period, batch, currency.
2. Summary table, one line per machine (and per site if several): machine · type · site · days worked · work h · OT h · standby h · breakdown h · gross · fuel · adjustments · net.
3. Fuel detail (date, machine, litres, price, amount, receipt no).
4. Adjustments detail (date, machine, type, reason, amount).
5. Grand total box: gross, total deductions, **net payable in words** (EN) and figures.
6. Signature boxes: our finance · project manager · vendor representative (acknowledgement).
7. Optional appendix (query `appendix=1`): D2 for each machine.

Sample S2 in this package shows the target look.

## D4 — Equipment Payroll Summary (A4 landscape)

Per vendor block: vendor header row, machines rows, vendor subtotal; batch grand total; KPIs at top (machines, vendors, hours, net). Used by finance for payment.

## D5 — Daily Site Equipment Report (A4 portrait)

Site, shift, date; table of every deployed machine with state, operator, in/out, downtime list, work hours, remarks; counts at the top; supervisor signature. No money.

## D6 — Utilization (Excel + PDF)

Per machine for the period: deployed days, working days, work h, standby h, breakdown h, utilization % = work / (deployed days × standard hours), availability % = 1 − breakdown / (deployed days × standard hours); per vendor subtotal. Sorted by lowest utilization (to spot idle rented machines).

# 8. Retention and integrity

- Scans and contract documents are never deleted by the application; voiding a batch never deletes files.
- `sha256` stored for every file; a nightly (or on-demand Admin) check `GET /api/equipment/admin/storage-check` may re-hash a sample and report mismatches (optional, phase 10).
- Back-up: when the S3 driver is used, enable bucket versioning; when the local driver is used on a Render persistent disk, include the disk in backups.
